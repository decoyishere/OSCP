# Privilege Escalation Windows

Use the PowerShell commands to inspect a Windows host. Each section shows what to run, how to interpret the evidence, and how the attack works. Replace example names and paths with the values you observe. Commands are read-only and credential checks report metadata.

### Finding → next check

| Finding                                              | Next check                                                     | Why                                                            |
| ---------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------- |
| An unquoted service executable path has spaces       | Actual executable boundary, directory ACLs and service account | Ambiguous parsing can select a different executable            |
| Your group can write to a service binary             | Exact file ACL, parent ACL and service identity                | A later service start can execute modified code                |
| Your group can change a service configuration        | Service object rights and service identity                     | Configuration controls what the service runs                   |
| A task runs as SYSTEM                                | Action, arguments, working directory and their ACLs            | A privileged task may consume files that another user controls |
| An enumeration tool flags an impersonation privilege | Actual token, process account and component prerequisites      | The privilege alone leaves the mechanism unconfirmed           |
| Procmon shows a failed DLL lookup                    | Later events for the same DLL and process, then directory ACLs | A miss may be one step in normal resolution                    |
| Windows Installer policy values both equal 1         | Verify the relevant user's HKCU context                        | The policy requires both values                                |
| Medium integrity and Administrators is deny-only     | Confirm account group and UAC policy                           | This is consistent with a filtered admin token                 |

### 1. Start with the current token and operating system

```powershell
whoami /all
Get-CimInstance Win32_OperatingSystem |
    Select-Object Caption, Version, BuildNumber, OSArchitecture
Get-LocalGroupMember -SID 'S-1-5-32-544'
```

**Look for** the account, groups, integrity level and privileges in the current token. Match this token's groups to the principals shown in ACLs. S-1-5-32-544 identifies the built-in Administrators group independently of display language. The local group command requires the LocalAccounts module and applies to systems with a local group database. On a domain controller, review domain group membership through administrative tooling. A privilege shown as Disabled is present in the token but currently disabled. A build number helps scope version-specific findings. Configuration and patch level can also matter.

#### Read the file and directory ACLs

```powershell
icacls.exe 'C:\Example\Agent\agent.exe'
icacls.exe 'C:\Example\Agent'
```

| Output        | Meaning                                                          |
| ------------- | ---------------------------------------------------------------- |
| (F), (M), (W) | Full control, modify, or write                                   |
| (RX)          | Read and execute                                                 |
| (I)           | Inherited entry                                                  |
| (OI), (CI)    | Entry can propagate to files or subdirectories, respectively     |
| (IO)          | Inherit-only. This entry applies through inheritance to children |

Compare what the principal can do to the specific object. A directory ACL and a file ACL can differ. Look at both when the finding depends on file creation, modification or replacement. Check applicable deny entries and group membership. Use the Windows Effective Access tab to resolve ambiguity.

### 2. Windows services

```powershell
Get-CimInstance Win32_Service |
    Select-Object Name, DisplayName, StartName, StartMode, State, PathName |
    Format-Table -Wrap

$serviceName = 'ExampleAgent'
sc.exe qc $serviceName
sc.exe query $serviceName
sc.exe sdshow $serviceName
```

**Look for** the internal service name, account, exact command line, state and startup mode. The service object's security descriptor and the executable's filesystem ACL are independent. Use sc.exe explicitly to avoid the sc alias in Windows PowerShell.

#### Unquoted service path

**Enumerate.** Inspect BINARY\_PATH\_NAME in the service configuration. Identify the complete executable path and inspect the relevant directory ACLs with icacls.exe.

**Look for** an unquoted executable path containing spaces, a low-privileged principal with write access where the path is ambiguous, and a service identity with greater privileges. Spaces in arguments are common. Auto-start describes how the service is launched and start/stop permissions govern who can control it.

**Attack mechanism.** Windows can resolve the ambiguous command line to an unintended executable. The selected program runs under the service account. Quoting the executable path and restricting directory writes removes the exposure.

#### Weak service object permissions

```powershell
accesschk.exe -c -v 'BUILTIN\Users' $serviceName
```

**Look for** SERVICE\_CHANGE\_CONFIG, WRITE\_DAC or WRITE\_OWNER granted to unexpected principals. Start/stop rights and configuration rights are checked separately. Supply the relevant user or group and use the localized group name if needed.

**Attack mechanism.** An overly permissive service object can let an untrusted principal control which program a privileged service runs. Permission to change the DACL or ownership can provide indirect control. Review the service object ACL.

#### Writable service executable or directory

```powershell
$executable = 'C:\xampp\mysql\bin\mysqld.exe'
icacls.exe $executable
icacls.exe (Split-Path -Path $executable -Parent)
```

**Look for** effective write or replacement rights held by a low-privileged principal on the exact executable or installation directory. Check the executable even when its service path is quoted.

**Attack mechanism.** When a privileged service starts, it loads code from a location controlled by a less privileged account. The service account sets the scope of the execution. Review installation directory ACLs and file integrity.

[Service security and access rights](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights) · [AccessChk](https://learn.microsoft.com/en-us/sysinternals/downloads/accesschk)

### 3. Token privileges and Potato-family attacks

```powershell
whoami /priv
whoami /groups
```

| Privilege                     | What it permits                                                   | Security relevance                                                                   |
| ----------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| SeImpersonatePrivilege        | Impersonate a client after authentication, subject to token rules | A service can act in a client's security context                                     |
| SeAssignPrimaryTokenPrivilege | Assign a process primary token in supported scenarios             | An eligible token already available to the caller can be used to create a process    |
| SeBackupPrivilege             | Bypass ordinary read ACL checks using backup semantics            | Protected data may be exposed                                                        |
| SeRestorePrivilege            | Bypass ordinary write ACL checks using restore semantics          | Protected files and ownership may be affected                                        |
| SeTakeOwnershipPrivilege      | Take ownership of securable objects                               | Ownership can allow a caller to change an object's DACL                              |
| SeDebugPrivilege              | Debug or open many processes beyond normal access checks          | Process data and control may be exposed. Protected processes have extra restrictions |

**Look for** rights assigned to accounts that have no operational need for them. Record the token state and account type. Local policy or a GPO can assign these rights.

**Attack mechanism.** Potato-family methods abuse privileged authentication or impersonation interactions to act in a more privileged context. Applicability depends on the relevant Windows component, usable token type, service configuration and patch state. Inspect the user-right assignment and the service's isolation.

[Windows privilege constants](https://learn.microsoft.com/en-us/windows/win32/secauthz/privilege-constants)

### 4. SeBackupPrivilege and protected data

```powershell
whoami /priv | Select-String 'SeBackupPrivilege|SeRestorePrivilege'
Get-CimInstance Win32_ComputerSystem | Select-Object Name, DomainRole
```

**Look for** these rights outside the expected backup operators or agents. DomainRole values 4 and 5 identify domain controllers. On member systems, the SAM contains local account data. AD DS directory data on a domain controller has domain-wide sensitivity.

**Attack mechanism.** Backup-aware operations can bypass ordinary read ACL checks. A caller that can exercise the backup privilege may gain access to protected data. Audit the user-right assignment and protect backup copies to the same standard as the underlying data.

### 5. Registry credentials and remote-access profiles

```powershell
$key = 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon'
Get-ItemProperty -LiteralPath $key |
    Select-Object AutoAdminLogon, DefaultUserName, DefaultDomainName
(Get-Item -LiteralPath $key).GetValueNames() -contains 'DefaultPassword'
cmdkey.exe /list

$locations = @(
    'HKCU:\Software\SimonTatham\PuTTY\Sessions'
    'HKCU:\Software\Microsoft\Terminal Server Client\Servers'
    'HKCU:\Software\TightVNC'
    'HKLM:\SOFTWARE\TightVNC'
    'HKLM:\SOFTWARE\RealVNC'
    'HKLM:\SOFTWARE\UltraVNC'
)
$locations | ForEach-Object {
    if (Test-Path -LiteralPath $_) {
        Get-ChildItem -LiteralPath $_ | Select-Object PSPath
    }
}
netsh.exe wlan show profiles
```

**Look for** an AutoLogon identity, whether the password value exists, and saved credential targets in the current user context. AutoLogon tooling may use a different store. PuTTY and RDP keys commonly reveal connection metadata. VNC paths vary with product, version, install mode and registry view. A saved Wi-Fi profile concerns network access and usually has separate impact from local Windows admin access.

**Attack mechanism.** An exposed reusable credential can allow someone to act as its owner. Assess the affected account's privileges, target scope and credential protection. The presence checks above do not print passwords.

### 6. Credential exposure in files, applications and memory

```powershell
$roots = @('C:\inetpub', 'C:\ProgramData', "$env:USERPROFILE\Documents")
$roots |
    Where-Object { Test-Path -LiteralPath $_ } |
    ForEach-Object {
        Get-ChildItem -LiteralPath $_ -File -Recurse -Force -ErrorAction SilentlyContinue
    } |
    Where-Object {
        $_.Name -match '^(\.env|unattend\.xml|sysprep\.inf|sitelist\.xml|ultravnc\.ini)$' -or
        $_.Extension -in '.config', '.bak', '.rdp', '.ppk', '.kdbx'
    } |
    Select-Object FullName, LastWriteTime, Length

if (Get-Module -Name PSReadLine) {
    $historyPath = (Get-PSReadLineOption).HistorySavePath
    Get-Item -LiteralPath $historyPath -ErrorAction SilentlyContinue |
        Select-Object FullName, LastWriteTime, Length
}

@(
    "$env:USERPROFILE\.git-credentials"
    "$env:USERPROFILE\.ssh"
    "$env:WINDIR\Panther\Unattend.xml"
    "$env:WINDIR\Panther\UnattendGC\Unattend.xml"
    "$env:WINDIR\System32\Sysprep\Sysprep.inf"
    "$env:LOCALAPPDATA\Microsoft\Credentials"
    "$env:APPDATA\Microsoft\Credentials"
) | ForEach-Object { Get-Item -LiteralPath $_ -Force -ErrorAction SilentlyContinue } |
    Select-Object FullName, LastWriteTime
```

**Look for** unexpected ownership or overly broad access on application configs, deployment artifacts, backup files and logs. Focus the search on the host's actual application directories. A filename match is a lead. Missing output can mean a path is absent, inaccessible or outside the selected roots. PSReadLine's history file belongs to the current user and host. Get-History covers the current PowerShell session.

```powershell
if (Get-Module -ListAvailable -Name WebAdministration) {
    Import-Module WebAdministration
    Get-ChildItem IIS:\AppPools | Select-Object Name,
        @{Name='IdentityType';Expression={$_.processModel.identityType}},
        @{Name='UserName';Expression={$_.processModel.userName}}
}
klist.exe
```

| Surface                                                             | Look for                                                                                    | Attack mechanism or impact                                                                            |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Unattend, Sysprep, web configs, legacy McAfee SiteList, VNC configs | Readable deployment files or backups                                                        | Configuration can retain reusable deployment or application secrets                                   |
| PowerShell history, IIS logs, Git settings, SSH keys, RDP files     | Weak ACLs and logging of command lines or URLs                                              | Operator workflows can accidentally persist authentication material                                   |
| Credential Manager and DPAPI                                        | User context, permissions and protected records                                             | Recoverability depends on data scope and protection context                                           |
| IIS application pools                                               | Custom account, built-in identity and effective rights                                      | Account exposure can reach other applications and resources that trust the identity                   |
| Scheduled Task metadata                                             | Principal, action and arguments                                                             | Task authors can embed secrets in arguments. Scheduler-managed credentials are separate from task XML |
| WinRM, Kerberos and LSASS                                           | Delegation settings, current session ticket cache metadata and credential-protection policy | Weakened protections or inappropriate delegation can expose identities beyond the current session     |

### 7. AlwaysInstallElevated

```powershell
reg.exe query 'HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer' /v AlwaysInstallElevated
reg.exe query 'HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer' /v AlwaysInstallElevated
```

**Look for** both values set to REG\_DWORD 0x1 in the relevant machine and user contexts. Record an enabled machine policy even if the current user's setting is absent.

**Attack mechanism.** When both settings are enabled, Windows Installer can elevate unmanaged MSI installations. That policy crosses the user-to-system boundary. Remove the unsafe policy and verify the effective settings.

[AlwaysInstallElevated](https://learn.microsoft.com/en-us/windows/win32/msi/alwaysinstallelevated)

### 8. Scheduled tasks

```powershell
Get-ScheduledTask | Select-Object TaskPath, TaskName, State,
    @{Name='RunAs';Expression={$_.Principal.UserId}},
    @{Name='RunLevel';Expression={$_.Principal.RunLevel}} |
    Format-Table -Wrap

$task = Get-ScheduledTask -TaskName 'Example Backup' -TaskPath '\'
$task.Actions | Format-List Execute, Arguments, WorkingDirectory
$task.Triggers | Format-List
$task | Get-ScheduledTaskInfo | Select-Object LastRunTime, NextRunTime, LastTaskResult

icacls.exe 'C:\Example\Backup\backup.ps1'
icacls.exe 'C:\Example\Backup'
```

**Look for** a more privileged run-as account and an action whose executable, script, working directory or dependency is controlled by a lower-privileged user. When Execute is a generic host such as powershell.exe, read Arguments to identify the script it invokes. Check the task state and triggers. Some tasks are event-driven and have no meaningful next run time. RunLevel by itself says little about which rights the task's account holds.

**Attack mechanism.** A scheduled task can launch or load altered content under its configured principal. The scheduler supplies the execution context and the weak ACL supplies control over the content. Protect both the task definition and all files and directories it trusts.

[Get-ScheduledTask](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/get-scheduledtask)

### 9. DLL search order and hijacking

```powershell
Get-CimInstance Win32_Service |
    Select-Object Name, StartName, ProcessId, PathName |
    Format-Table -Wrap

[Environment]::GetEnvironmentVariable('Path', 'Machine') -split ';'
icacls.exe 'C:\Example\Agent'
```

**Enumerate.** Review the application or service's registered path and account. In Sysinternals Process Monitor, filter a capture to the relevant process or PID, then review DLL filesystem lookups and successful Load Image events. Access to a host-wide capture generally requires administrative rights. Keep failed and successful events visible when interpreting the sequence.

**Look for** a privileged process searching a directory that a less privileged user can write to, and evidence that the directory actually participates in resolution for the particular DLL. Match events by process instance and DLL name. PATH is only one possible source of directories. The configured machine PATH may also differ from the process environment. A NAME NOT FOUND event alone is common and only shows that one lookup missed.

**Attack mechanism.** If an application requests a DLL by name and the loader resolves it to a directory an untrusted user controls, the application can load unintended code with its own privileges. Search order, manifests, KnownDLLs and loader flags can affect where the DLL is resolved. Use a trusted full path or restrictive loader configuration and protect participating directories.

[Dynamic-link library security](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-security) · [Process Monitor](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon)

### 10. Defender and AV evasion

```powershell
Get-MpComputerStatus | Select-Object AMRunningMode, AntivirusEnabled,
    RealTimeProtectionEnabled, IsTamperProtected, AntivirusSignatureLastUpdated

Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-Windows Defender/Operational'
    Id = 1116, 1117, 5007
} -MaxEvents 30 | Select-Object TimeCreated, Id, ProviderName
```

**Look for** the Defender operating mode, real-time and tamper protection status, signature freshness, and event timestamps. 1116 records a detection, 1117 records an action and 5007 records a configuration change. Correlate event times with the relevant administrative action or incident. Defender cmdlets and event access depend on the endpoint configuration and permissions. Where a different product is primary, review that product's status and logs.

**Attack mechanism.** Defense evasion attempts to reduce the chance that endpoint controls will detect or block an action. Static file scanning, script inspection through AMSI and behavior monitoring observe different signals. A configuration change or blocked action belongs in the timeline and does not independently establish elevation.

[Microsoft Defender Antivirus events](https://learn.microsoft.com/en-us/defender-endpoint/troubleshoot-microsoft-defender-antivirus)

### 11. UAC and filtered administrator tokens

```powershell
whoami /groups

$uac = 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System'
Get-ItemProperty -LiteralPath $uac | Select-Object EnableLUA,
    ConsentPromptBehaviorAdmin, ConsentPromptBehaviorUser, PromptOnSecureDesktop
```

**Look for** the current integrity level, Administrators group membership and whether that group is deny-only in the token. Medium Mandatory Level has SID S-1-16-8192 and High Mandatory Level has SID S-1-16-12288. Read UAC policy in the context of the actual account and token.

**Attack mechanism.** UAC bypass techniques can abuse trusted elevation behavior to take a split-token administrator from medium to high integrity without the expected prompt. Auto-elevated component behavior varies with build and policy. Standard users require an administrator's credentials for authorized elevation.

[How User Account Control works](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works)

### 12. Enumeration tools and how to verify their findings

| Tool or output                    | Use                                                                    | Verify with                                                                             |
| --------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| WinPEAS report                    | Review leads across services, tasks, privileges and host configuration | Inspect the item with the native commands in the relevant section                       |
| PowerUp report                    | Review candidate service, installer and ACL findings                   | Confirm exact object, effective rights and run-as account                               |
| Seatbelt report                   | Review security posture and configuration inventory                    | Compare values with Windows policy and expected host role                               |
| AccessChk                         | Review service object permissions                                      | Compare the output to the principals in the current token and the service configuration |
| Process Monitor                   | Review runtime file lookups and DLL loading                            | Correlate process ID, filename, event order and directory ACLs                          |
| PowerShell, icacls.exe and sc.exe | Confirm identity, policy, paths and rights                             | Capture the exact command and relevant lines of output                                  |

#### Worked example

A scan flags a writable service installation under C:\xampp. Service configuration shows that the binary is C:\xampp\mysql\bin\mysqld.exe and runs as LocalSystem. The service command line correctly quotes the executable. The binary ACL grants Authenticated Users modify permission, and that group is enabled in the reviewed token. Those details support a **writable service executable** finding. If the scan had only shown that the service ran as LocalSystem, the missing evidence would be effective control over the file, its dependencies or the service object.

For each finding, record the lower-privileged identity, the exact object it controls, the higher-privileged principal that uses it, and when that use occurs. Include the supporting output and redact sensitive metadata before sharing.
